Product

Three steps, every run recorded

Workflows are data, not code. Each step calls one provider capability; dependencies decide what runs in parallel. No model decides control flow.

  1. 1

    Define

    Describe steps, inputs and dependencies as JSON. Validation catches cycles, missing references and unsafe schemas before anything runs.

  2. 2

    Run

    The coordinator executes the DAG with bounded parallelism, per-attempt timeouts, retries with backoff and fallback between compatible providers.

  3. 3

    Verify

    Outputs are checked against JSON Schema and explicit criteria, with evidence stored per check — and an honest note on what was not verified.

Capabilities

Built for work you need to trust

Orchestration

Dependency-ordered steps, parallel stages, templated inputs between steps, cancellation and execution timeouts — with per-step status, attempts and duration persisted.

  • Up to 50 steps per workflow
  • continueOnError and dependency skipping
  • Interrupted runs flagged on restart

Verification

JSON Schema plus criteria such as min_items, contains and urls_in_step, which traces cited URLs back to the search results they came from.

  • Evidence recorded for every check
  • Structure and citations — never “facts verified”
  • Optional: fail the step on failure

Observability

Structured, redacted logs with request IDs; provider latency, errors, tokens and estimated cost where reported; execution history and an audit trail.

  • Liveness and readiness checks
  • Secrets scrubbed before logging
  • Per-provider error breakdown

Provider integrations

Adapters for Anthropic Claude, Google Gemini, Jina AI, Tavily, Exa and GitHub, behind one contract per capability. Each stays disabled until its key is configured on the server.

  • Keys never leave the server
  • Fallback only between compatible providers
  • SSRF guard on URL inputs

Console

One place to see every run

The console shows providers, workflows, executions, verification evidence and metrics — read straight from your server.

Developers

A small, predictable API

Versioned under /api/v1, bearer-token auth, one response envelope, request IDs on every response.

  • Success: { data, meta: { requestId } }
  • Errors: { error: { code, message, details } }
  • Executions start with 202; poll until finished
  • Records are scoped to their owner
Create a workflow, then run it 
export OAT=http://localhost:3000/api/v1
export TOKEN=oat_your_token_here

# 1. Create the workflow (see "Workflow JSON")
curl -s "$OAT/workflows" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d @workflow.json

# 2. Start an execution (returns 202 with an id)
curl -s "$OAT/workflows/wf_.../executions" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"input":{"topic":"vector databases"}}'

# 3. Poll the execution until it finishes
curl -s "$OAT/executions/ex_..." \
  -H "Authorization: Bearer $TOKEN"
Run and wait (Node 18+ or browser) 
const BASE = 'http://localhost:3000/api/v1';
const headers = {
  Authorization: `Bearer ${process.env.OAT_TOKEN}`,
  'Content-Type': 'application/json',
};

async function call(path, init = {}) {
  const res = await fetch(BASE + path, { headers, ...init });
  const body = await res.json();
  if (!res.ok) throw new Error(`${body.error.code}: ${body.error.message}`);
  return body.data;
}

const run = await call('/workflows/wf_.../executions', {
  method: 'POST',
  body: JSON.stringify({ input: { topic: 'vector databases' } }),
});

let execution = await call(`/executions/${run.id}`);
while (['queued', 'running'].includes(execution.status)) {
  await new Promise((r) => setTimeout(r, 1500));
  execution = await call(`/executions/${run.id}`);
}
console.log(execution.status, execution.steps);
workflow.json 
{
  "name": "Research brief",
  "inputSchema": {
    "type": "object",
    "required": ["topic"],
    "properties": { "topic": { "type": "string" } }
  },
  "steps": [
    {
      "id": "search",
      "capability": "web.search",
      "input": { "query": "{{input.topic}}", "count": 5 }
    },
    {
      "id": "summary",
      "capability": "llm.generate",
      "dependsOn": ["search"],
      "input": {
        "prompt": "Summarize {{input.topic}} and cite URLs: {{steps.search.output.results}}"
      },
      "verification": {
        "criteria": [
          { "type": "urls_in_step", "path": "text", "sourceStep": "search" }
        ]
      }
    }
  ]
}

Documentation

Get started in four steps

Everything runs locally with Node 22.13 or newer. Provider keys are optional — each integration stays off until configured.

  1. 1Install

    shell
    npm install
cp .env.example .env

  2. 2Create a token

    shell
    npm run token:create -- alice admin

    Add the printed alice:admin:<hash> entry to AUTH_TOKENS. Only the hash is stored.

  3. 3Configure providers

    Set any of ANTHROPIC_API_KEY, JINA_API_KEY, TAVILY_API_KEY, EXA_API_KEY, GITHUB_TOKEN. For a dry run, set ENABLE_MOCK_PROVIDERS=true — output is clearly labelled [MOCK].

  4. 4Build and run

    shell
    npm run build
npm start

    Then open the console and paste your token.
